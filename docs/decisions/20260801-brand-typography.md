# Brand typography: one type system across marketing and product

**Date:** 2026-08-01
**Status:** Accepted

## Context

ShellTeam's marketing site (`shellteam.sh`) and its product (dashboard +
cockpit) had drifted into two different type systems:

| Surface | Sans | Mono | Display |
|---|---|---|---|
| Marketing site | IBM Plex Sans | IBM Plex Mono | Instrument Serif |
| Dashboard / cockpit | Figtree | JetBrains Mono | none |

Neither set was chosen; both were reached for. That turned out to matter (see
"Which faces" below).

The palette was already shared (`#110f0d` ink, `#f59e0b` amber), so the two
read as related but not as the same product. That gap is felt at the worst
possible moment: immediately after someone pays, when the page they bought from
and the thing they land in should obviously be the same company.

Two further problems surfaced while looking at this:

1. **The marketing site used monospace as its interface font.** Nav, buttons,
   feature headings, plan names, FAQ and all fine print were set in IBM Plex
   Mono. For the audience we now sell to (people leaving an AI app builder, per
   [20260801-gtm-app-builder-graduates.md](20260801-gtm-app-builder-graduates.md)),
   a monospace interface reads as "this is a tool for people who live in a
   terminal", which directly contradicts the page's own "you don't need to know
   how to code" argument.

2. **Every HTML surface loaded fonts from Google.** Six files carried a
   `fonts.googleapis.com` link, and the CSP explicitly allowed
   `fonts.googleapis.com` / `fonts.gstatic.com`. Everything else third-party
   (xterm, marked) was already self-hosted "for CSP hardening". Fonts were the
   last exception, which sat badly next to the product's own "no telemetry,
   nothing phones home" claim, and meant a box with no outbound network
   rendered the cockpit in a fallback face.

## Decision

**One type system across both surfaces, self-hosted.**

- `--font-sans`: **Libre Franklin**. `--font-mono`: **Spline Sans Mono**.
  `--font-serif`: **Zilla Slab** (display only).
- **Mono is reserved for things that ARE code**: code, paths, URLs, terminal
  output, and the address field in the reserve widget. Interface text is always
  sans. This is written as a rule at the top of both stylesheets, because the
  drift it prevents is easy to reintroduce one component at a time.
- Serif is used sparingly for display moments only: marketing headlines and the
  cockpit's empty-state title. It is the strongest "same brand" signal we have
  and it stops working if it spreads.
- All three faces are self-hosted as woff2 (latin + latin-ext) under
  `frontend/static/vendor/fonts/` and `computer/ai-chat/public/vendor/fonts/`,
  regenerated by `scripts/fetch-brand-fonts.py`. Google Fonts is removed from
  the CSP.

### Which faces, and the banned-fonts list

The first version of this decision kept IBM Plex + Instrument Serif and deleted
those two entries from Impeccable's `reflex_fonts_to_reject` list in
`tests/test_design_system.py`, arguing that the list catches *reflexive* choices
and should not veto a deliberate brand.

That argument was wrong and the override has been reverted. The list's stated
reason is:

> Reject every font that appears in the reflex_fonts_to_reject list. **They are
> your training-data defaults and they create monoculture across projects.**

The premise was that these faces were a deliberate human brand choice. They were
not: the marketing site's typography was itself picked by an agent, from exactly
the list of faces an agent reaches for by reflex. The guard was doing its job and
the override defeated it.

The faces were re-picked by running the skill's `font_selection_procedure`
instead of by reflex:

1. **Brand words:** *warm, sturdy, plain-spoken*. The physical object is a piece
   of equipment with a printed manual, not a piece of software. Deliberately not
   "modern" or "elegant".
2. **Reflex picks, written down and rejected:** IBM Plex Sans, Instrument Serif,
   and a geometric grotesque in the Inter/Space Grotesk family. All three are on
   the reject list, which confirmed the diagnosis.
3. **Catalog pass**, then rendered against the real hero at 1440px before
   committing to anything.

Result: **Zilla Slab** (display, true italic, Mozilla's slab — mechanical but
human, and it carries the amber italic emphasis the layout leans on),
**Libre Franklin** (interface — a Franklin Gothic revival, sturdy and plain at
UI sizes), **Spline Sans Mono** (code, designed as a code companion).

The full ban list is restored, with `Space Mono` added back as well. Nothing is
exempt: if a brand face ever lands on that list, the face is wrong, not the list.
The test also asserts positively that the brand faces are what `tokens.css`
declares, so silent drift in either direction fails.


## Consequences

- The dashboard, cockpit, file editor and marketing site share one type system.
  The marketing site self-hosts the same bundle under `assets/fonts/`, so
  shellteam.sh now makes zero third-party requests of any kind.
- No page load reaches a third party for fonts. `font-src` is `'self'`, and
  `tests/test_hardening_v3.py::TestNoThirdPartyFonts` fails the build if any
  shipped HTML or CSS reintroduces a font CDN.
- ~410 KB of woff2 per vendor directory, duplicated in two (the cockpit is a
  separate service on its own port and cannot import the dashboard's tokens).
  Browsers fetch only the subsets they need; a cockpit load pulls ~140 KB.
- Three new packages in `third_party/vendor-manifest.json` with per-file hashes,
  license texts under `third_party/licenses/`, and NOTICE attribution. All three
  faces are SIL OFL 1.1, which permits redistribution.
- The `.woff2` MIME type was missing from the cockpit's static server
  (`lib/constants.mjs`); fonts were served as `application/octet-stream`.
  Fixed, and it takes effect at the next `shellteam-ai-chat` restart.

## What would make us revisit

- If the marketing brand changes faces, this becomes stale immediately: the
  whole point is that the two surfaces move together, so change both or neither.
- If licensing on either family changes away from OFL, the self-hosted copies
  have to go back to a CDN or be replaced.
- If the cockpit ever gets to import the dashboard's `tokens.css` directly
  (same origin), the duplicated vendor directory should collapse to one.
